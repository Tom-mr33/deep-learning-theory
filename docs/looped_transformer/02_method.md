# 02 · 方法：输入注入、截断窗口损失、b/T 怎么选

## 2.1 问题形式化（Sec. 3）

- `F`：`R^d` 上的函数类；`D_F` 其上的分布；`D_X` 输入的分布
- 采样 `f ~ D_F`，`x_1..x_k, x_test ~ D_X`
- prompt `P = (x_1, f(x_1), ..., x_k, f(x_k), x_test)`
- 学习系统 `M` 输出 `M(P)`，损失 `(M(P) − f(x_test))²`

基线架构：GPT-2 decoder，标准 `L=12`，循环 `L=1`。

## 2.2 循环结构与输入注入（Sec. 4.1）

定义 prompt 前缀 `P^i = (x_1, f(x_1), ..., x_i, f(x_i), x_{i+1})`（即"用 i 个样本去预测第 i+1 个"）。循环 t 次后的输出：

```
Y_t(P^i | θ) = M_θ( M_θ( ... M_θ( Y_0^i + P^i ) + P^i ) ... + P^i )
                       └──────────── t 次 ────────────┘
Y_0^i = 0
```

一句话：**`Y_{t+1} = M_θ(Y_t + P)`，初始为 0**。

对比三种变体：

| 变体 | 递推式 | 行为 |
|---|---|---|
| 权重绑定（Universal Transformer 式） | `Y_{t+1} = M(Y_t)`, `Y_0 = P` | t 增大后初值影响消失，t 超过训练值即**发散**（Fig.3） |
| **输入注入（本文）** | `Y_{t+1} = M(Y_t + P)` | 每步都把"题目"重新注入，固定点满足 `Y* = M(Y* + P)`，等于把 P 解了出来 |
| DEQ（隐式模型） | `Y = M(Y + P)`，用求根器解 | 需要 Jacobian 正则、调参难（Bai et al. 2021）——本文不这么做，直接展开固定次数 |

**为什么 `+P` 是关键**：不动点方程 `Y* = M(Y* + P)` 的解**依赖 P**；而去掉注入后 `Y* = M(Y*)` 的解与 P 无关（Bai et al. 2019 的观察：影响随 t 指数衰减）。这就是"发散"的机理——不是数值爆炸，而是**解与输入脱钩**。

## 2.3 损失函数（Eq. 1，全文核心公式）

```
min_θ  E_P [ 1/(b − b_0) · Σ_{t=b_0}^{b}  1/(k+1) · Σ_{i=0}^{k}  l( Y_t(P^i|θ), f(x_{i+1}) ) ]
```

逐项拆：

| 符号 | 含义 | 备注 |
|---|---|---|
| `b` | 训练时的**最大循环次数** | 决定前向要展开多少步、也决定推理成本 |
| `b_0 = max(b − T, 0)` | 窗口起点 | |
| `T` | **截断窗口长度** | 只对最后 T 次循环算损失，省显存 |
| `i` | 前缀下标，`0..k` | 一个 prompt 提供 `k+1` 个训练信号 |
| `1/(b−b_0)` | 沿循环维平均 | 让每个循环步权重相同 |

两个设计要点：

1. **一个 prompt 出 k+1 个监督信号**。因为 decoder 是因果的，位置 `2j`（即 `x_{j+1}`）的输出天然只看得到前 `j` 对样本——所以一次前向就得到所有前缀的预测。*本仓库的实现正是利用这一点*：只做一次前向，在偶数位置收集预测（见 `src/looped/data.py` 与 `model.py` 的注释），比论文描述的字面做法（对每个 i 单独组 batch）省 k 倍算力，且数学等价。
2. **截断 = BPTT 的截断版**。全窗口反传需要存 b 次中间激活；`T=15, b=20` 只存 15 步。

## 2.4 b 与 T 的选择（Sec. 4.2，Fig.4）

两个旋钮，一对权衡：

| | 调大 | 调小 |
|---|---|---|
| **b** | 更容易找到稳定不动点；但收敛变慢、算力/显存上升 | 超过 b 的迭代会发散（不鲁棒） |
| **T** | 精度更好 | 省显存；精度下降；太大则训练不稳（梯度波动） |

经验结论：

- `b ≤ 12`（= 标准模型的深度）**不够**，达不到 12 层模型的效果。
- 模型总是**在 b 之前就饱和**（因为目标函数只要求 b 步内匹配）。
- 存在饱和点：`T=15` 时 `b=40` 与 `b=50` 收敛速度几乎相同。所以选**刚好不发散的最小 b**。
- 作者的选择标准：`b` = 能阻止"训练后期发散"的最小值；`T` = 能保证精度的最小值。→ linear (20,15)、sparse (20,10)、tree (70,15)、MLP (12,5)。

⚠️ **这是逐任务网格搜索出来的**，不是理论导出。作者把 (b, T) 解释为"任务对 Transformer 的难度度量"（Sec. 6），但 2-layer ReLU NN 有 ~2000 个参数却只要 (12,5)，而决策树只有 31 个参数却要 (70,15)——**这个"难度度量"在论文自己的数据上就自相矛盾**，作者也承认"原因不明"。

## 2.5 训练细节

- 优化器 Adam，`lr = 1e-4`，**无** weight decay / 梯度裁剪 / 数据增强（为了和 Garg et al. 公平比较）
- curriculum：`d` 与 `k` 从小到大（沿用 Garg et al.）
- **b 的调度**：`b` 从 1 逐步升到目标值，损失窗口从 `[1, T]` 平移到 `[b−T, b]`
  - 作者特意说这不叫 curriculum learning：因为 `[1,T]` 比 `[b−T,b]` **更难**（要在更少迭代内收敛），实际作用是"热身"
  - 消融（App. E, Fig.17）：大多数任务影响不大；决策树上略好 → 全部实验都开着

## 2.6 参数量的算术核对

单层 GPT-2 块（D=256，MLP 4×）：

| 组件 | 参数量 |
|---|---|
| c_attn (3D×D) + c_proj (D×D) | 3·256² + 256² ≈ 0.26M |
| MLP (D×4D + 4D×D) | 2·256·1024 ≈ 0.52M |
| LayerNorm ×2 | ~1k |
| **单块合计** | **≈ 0.79M** |

- 循环模型 = 单块 0.79M + 嵌入/readout（20×256 + 256 + pos 81×256 + readout 256 ≈ 26k）
- 标准模型 = 12 × 0.79M ≈ 9.4M ✓ 与论文 9.48M 对得上

→ **"1/12 参数"的本质就是"1 块 vs 12 块"**，没有魔法。真正的问题是：省下的参数能不能换成算力上的好处？论文没测。

## 2.7 一个容易被忽略的细节

论文推理时用的是 `b` **之后**的迭代（Fig.2 左跑到 100 次）。也就是说：

- 训练成本 ∝ `b`（前向）+ `T`（显存/反传）
- 推理成本 ∝ 想要的迭代次数（可达 100）
- 收益是"参数少"，代价是"推理时前向次数多"

**参数量与算力被解耦了**，这是循环架构真正的卖点（可以做"深度自适应"：难的样本多循环几次），也是全文最该做而没做的实验（详见 04、05）。
